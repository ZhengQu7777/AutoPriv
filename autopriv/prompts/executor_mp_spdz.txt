Backend: MP-SPDZ
Reference: https://mp-spdz.readthedocs.io/en

MP-SPDZ is a framework implementing many multi-party computation (MPC) protocols. Users write a high-level program in a Python-like DSL saved as Programs/Source/<name>.mpc, compile it with ./compile.py, then run it with a protocol-specific script under Scripts/.

Write task logic as MP-SPDZ high-level .mpc code:
- Use sint (secret integer), sfix (secret fixed-point), cint (clear integer) types from the Compiler.
- Inputs: sint.get_input_from(player_id) reads a secret input from party player_id.
- Outputs: .reveal() reveals a secret value; print_ln('%s', x.reveal()) prints it.
- Arrays and loops: use Array/Matrix and @for_range for compile-time loops over public ranges; @for_range_opt for optimized parallel loops.
- Comparisons: a == b, a < b, a > b produce secret booleans (sint with value 0/1).
- For PSI implemented in MP-SPDZ, a simple approach is pairwise secret equality comparison over two input arrays; optimization via sorting is out of scope for the minimal demo.

Compilation command:
  ./compile.py -R 64 <program_name>
  Flags:
    -R <bits>: ring size in bits (typical 64 or 128)
    -F <bits>: prime field size (alternative to -R)
    -Z <bits>: binary circuit

Run scripts under Scripts/ pick a protocol. Map configer output to protocol:
- mode=online + profile=balanced/latency_optimized  → semi-honest 2PC: Scripts/semi2k.sh  (ring-based, 2 parties, semi-honest)
- mode=online + profile=low_bandwidth              → Scripts/semi2k.sh (still 2PC ring)
- mode=offline_precompute                          → Scripts/mascot.sh (malicious, requires offline phase) if security needed
- n>2 parties implied by task                      → Scripts/replicated-ring-party.sh (3PC semi-honest)

Default to Scripts/semi2k.sh for 2PC semi-honest PSI unless configer/instruction suggests otherwise.

Run command format: ./Scripts/<protocol>.sh <program_name>

Generated file conventions:
- mpc_file.name: <task_type>_task.mpc  (e.g. psi_task.mpc)
- sh_file.name:  run_<task_type>.sh    (e.g. run_psi.sh)

mpc_file.content requirements:
- Start with a one-line top comment in the form: "# <task_type> via MP-SPDZ — generated by AutoPriv executor"
- Include minimal PSI / task logic with clearly marked INPUT_SIZE constant derived from configer.parallelism or a small default (e.g. 8).
- Use compile-time constants for party counts; read inputs via sint.get_input_from().
- End with a print_ln of the result for verification.

sh_file.content requirements:
- Line 1: "#!/usr/bin/env bash"
- Line 2: "set -euo pipefail"
- Expect MP-SPDZ root directory to be pointed by $MP_SPDZ_HOME (env variable), fall back to "../MP-SPDZ" if not set.
- Copy the generated .mpc file into $MP_SPDZ_HOME/Programs/Source/
- Run ./compile.py with appropriate flags from the backend mapping above.
- Run ./Scripts/<protocol>.sh on the program and capture stdout.
- Echo wall-clock time via /usr/bin/time -v or time; echo the protocol name and configer-derived parameters so the user can see what was actually executed.
- Exit with the protocol return code.

Parallelism mapping: use configer.parallelism as an informational parameter, e.g. exported to the script as THREADS=<parallelism>. MP-SPDZ does not expose a uniform --threads flag for all scripts; surface it in echo lines and as an env variable for future use.

Keep the generated files minimal and correct over clever: the user should be able to run the .sh on a machine where MP-SPDZ is installed and see output.
