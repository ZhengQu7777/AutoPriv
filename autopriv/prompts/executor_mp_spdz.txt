Backend: MP-SPDZ
Reference: https://mp-spdz.readthedocs.io/en

MP-SPDZ is a framework implementing many multi-party computation (MPC) protocols. Users write a high-level program in a Python-like DSL saved as Programs/Source/<name>.mpc, compile it with ./compile.py, then run it with a protocol-specific script under Scripts/.

======================================================================
A. .mpc FILE FORMAT — MANDATORY RULES (apply to any task, not just PSI)
======================================================================

1. .mpc files are compiled as FLAT SCRIPTS, not imported as modules.
   - DO NOT wrap logic in a `def main():` function.
   - DO NOT use `if __name__ == '__main__':` guards.
   - Write all top-level program logic directly at module scope.

2. Imports — either style works, pick ONE:
   - Simple: `from Compiler import sint, sfix, cint, print_ln`
   - Explicit: `from Compiler.types import sint, sfix, cint, Array, Matrix`
               `from Compiler.library import print_ln, for_range, for_range_opt`

3. Types:
   - sint — secret integer (shared among parties, values hidden)
   - sfix — secret fixed-point
   - cint — CLEAR integer (public to everyone); use only when the value is genuinely public
   - Array / Matrix — containers; e.g. `sint.Array(N)` for a length-N secret int array

4. Accumulators of secret values MUST be secret.
   - WRONG: `count = cint(0); ... count.update(count + secret_bool)`
   - RIGHT: `count = sint(0); ... count.update(count + secret_bool)`
   Mixing cint with sint operands silently breaks the computation.

5. Inputs: `sint.get_input_from(party_id)` reads one secret input from the named party's Input-P<party_id>-0 file.

6. Loops:
   - `@for_range(N)` — compile-time sequential loop over a public integer range
   - `@for_range_opt(N)` — compiler picks an optimization strategy (parallel, unrolled)
   - Public loop bounds only (N must be a Python int or cint).

7. Output: `value.reveal()` opens a secret to the clear, then use `print_ln('format', clear_val)` to print.

8. For n>2 parties, document the party count as a top-level constant, and ensure the chosen protocol script supports that count.

======================================================================
B. PROTOCOL SELECTION (map configer output → MP-SPDZ Scripts/*)
======================================================================

- 2PC + semi-honest (online, balanced, latency_optimized, low_bandwidth) → Scripts/semi2k.sh  (ring-based, 2 parties)
- 2PC + malicious or offline_precompute                                  → Scripts/mascot.sh  (malicious, field-based)
- 3PC semi-honest (implied by task or >2 parties)                        → Scripts/replicated-ring-party.sh
- Default when uncertain: Scripts/semi2k.sh

Use the configer output to pick; if unsure, semi2k.

======================================================================
C. .sh FILE FORMAT — MANDATORY RULES
======================================================================

The .sh is a single-host helper: copy the .mpc into MP-SPDZ tree, compile, run via the protocol script. It should be runnable on any machine where MP-SPDZ is installed, without user editing.

Required structure:

```bash
#!/usr/bin/env bash
set -euo pipefail

# 1) Locate MP-SPDZ root via env variable; fail clearly if unset or invalid.
MP_SPDZ_HOME="${MP_SPDZ_HOME:-$HOME/mp-spdz}"
if [[ ! -x "$MP_SPDZ_HOME/compile.py" ]]; then
    echo "Error: MP_SPDZ_HOME ($MP_SPDZ_HOME) does not look like an MP-SPDZ install." >&2
    echo "Set MP_SPDZ_HOME to the directory containing compile.py and Scripts/." >&2
    exit 1
fi

# 2) Resolve this script's directory, so we can copy the .mpc sitting next to it.
SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
PROGRAM="<program_name_without_extension>"
PROTOCOL="<protocol_name>"        # e.g. semi2k / mascot / replicated-ring-party

# 3) Copy the .mpc into MP-SPDZ source tree.
cp "$SCRIPT_DIR/${PROGRAM}.mpc" "$MP_SPDZ_HOME/Programs/Source/"

# 4) Compile. Use plain program name; do NOT pass -R unless required.
cd "$MP_SPDZ_HOME"
./compile.py "$PROGRAM"

# 5) Remind user about Player-Data inputs (one line per secret input per party).
echo "Reminder: ensure $MP_SPDZ_HOME/Player-Data/Input-P0-0 and Input-P1-0 (or more for n-party) are prepared."

# 6) Run via the protocol wrapper script with explicit program name argument.
./Scripts/${PROTOCOL}.sh "$PROGRAM"
```

Rules for generating the .sh:
- DO NOT hardcode absolute user paths like /home/<user>/ or /Users/<user>/.
- DO NOT pass -R/-F flags to compile.py unless the task truly requires a specific ring/field size; defaults are usually correct.
- DO NOT wrap the run command in /usr/bin/time -v (not always available on macOS); if wall-clock is desired, use the bash built-in `time` before `./Scripts/...`.
- Use `./Scripts/<protocol>.sh "$PROGRAM"` (program as explicit arg) so it runs our generated program rather than the script's default demo.
- Surface configer-derived PARALLELISM as an echoed environmental hint (MP-SPDZ does not accept a uniform --threads flag; do not invent one).
- Keep the script self-contained and idempotent: re-running should overwrite Programs/Source/<program>.mpc and re-compile cleanly.

======================================================================
D. FILE NAMING
======================================================================

- mpc_file.name: <task_type>_task.mpc   (e.g. psi_task.mpc, pir_task.mpc)
- sh_file.name:  run_<task_type>.sh     (e.g. run_psi.sh, run_pir.sh)
- mpc top comment: "# <task_type> via MP-SPDZ — generated by AutoPriv executor"

Keep the generated artifacts minimal and correct over clever. Correctness beats optimization for the first pass.
